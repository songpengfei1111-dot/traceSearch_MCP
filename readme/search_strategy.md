# 基本操作，截取感兴趣的行的context
- 如果想分析某行的寄存器从哪里来，可以以目标行为结尾，获取其前方的一些行作为context来辅助分析
- 如果遇到内存操作，比如想知道下面的58 从何而来
```text
78eb750de4 [13ede4]	ldrb w10, [x1]		 (mr) 78eb7f296a  (w) w10=0x58 
ld____ 78eb7f296a 4 58
可以搜索 78eb7f296a 获取其内存读写相关的信息
或者直接搜索 st____ 78eb7f296a 获取更精准的定位信息
然后基于 st____ 78eb7f296a 所定位到的行进一步获取其context
```

- 由于加密算法一般会涉及循环，所以当你认为定位到关键指令时，可以通过这条指令的汇编，比如 `eor w8, w0, w28` 来环比验证结论
- 不要直接搜索某些简单模式，比如 `=0x36` 这种会有大量的匹配，无法提供有用信息
- 每一轮开始搜索之前都要告诉用户，你的搜索目的是什么，并重新思考如何更精确地定位目标，而不要模糊搜索导致结果爆炸
- 搜索时可以不使用转义符

# 如何阅读搜索结果
如果搜索结果的数量大于等于 50，代表搜索的条件可能太过宽松了，
需要重新调整搜索策略和范围，比如仅搜索当前行之前的符合条件的信息，或者添加更严格的指令筛选条件

78eb750de4 [13ede4]	ldrb w10, [x1]		 (mr) 78eb7f296a 
或者使用 [13ede4] 还可以 (mr) 78eb7f29 来定位, where

# 定位开始搜索的点
对于某个感兴趣的值，先搜索其特征，观察其在trace中出现的规律
比如已知密文 840480a30000267b86a1b0f7e6814449319585f86f7f2056e72f 可以分段
8404 80a30000 267b86a1b0f7e6814449319585f86f7f2056e72f
最前面的8404是固定值，而最后的40长度是某种密文，那我们先通过搜索8404观察这一段整体的生成模式，
然后再具体观察后的40长度的生成方式

如果观察到
String__ 7c675a1b20—>84048
String__ 7c675a1b20—>840480
String__ 7c675a1b20—>840480a
这样的模式，显然，这里在进行字符串拼接，那么需要找到其拼接的数字的逻辑，以及值从何处来

注意，很多密文都是有多个部分拼接组成的，所以要考虑验证问题

注意，如果在搜索时同时出现两个未知变量，那么这两个变量的生成方式都应该进行溯源
比如 add x0,x1,x2 其中x0是目标值，而x1，x2都是变量，那么要分别追溯其生成逻辑

在得到阶段性的结论后，要尝试使用python代码验证目前的结论是否正确，可以计算出来


# 终止条件
在搜索生成逻辑时应该深度优先，比如，先追踪到一个字节的最原始信息，比如，
某个明文text的md5
某些libc/env 调用获取到的值（time/num...）

然后再追一个字节，验证猜想是否正确

最后总结流程，再进行正向推导验证
